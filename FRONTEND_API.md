# RSL Translator — API для фронтенда

HTTP `http://127.0.0.1:8000`, WebSocket `ws://127.0.0.1:8000`.
Для localhost можно использовать те же порты. Локальные CORS origins
фронтенда — localhost/127.0.0.1 на 5173 и 3000.

## Комнаты

1. Создай комнату через `POST /rooms` без тела. Ответ 200
   `{"room_id": "случайный ID"}`.
2. Добавь ID в ссылку на страницу комнаты своего фронтенда и передай ссылку
   собеседнику. Сервер возвращает ID, ссылку собирает фронтенд.
3. Проверь `GET /rooms/{room_id}`. Ответ 200
   `{"exists": true, "participants": 0}`. Отсутствующая комната — 404
   `{"detail": "Комната не найдена"}`.
4. Подключись к `/ws/{room_id}?role=sign` или `?role=speech`.
   В комнате по одному участнику каждой роли, всего максимум два.

Комнаты хранятся в памяти одного процесса. После отключения последнего
участника комната удаляется. При перезапуске сервера комнаты теряются.
Для нового звонка создай новую комнату.

## WebSocket

Отправляй JSON текстовыми WebSocket-сообщениями.

| Событие | Кто отправляет | Поля |
| --- | --- | --- |
| `joined` | Сервер вошедшему | `room_id`, `role`, `participants` |
| `peer_joined` | Сервер собеседнику | `role` вошедшего |
| `offer` | Клиент собеседнику через сервер | `data` — объект WebRTC offer |
| `answer` | Клиент собеседнику через сервер | `data` — объект WebRTC answer |
| `ice_candidate` | Клиент собеседнику через сервер | `data` — объект ICE-кандидата |
| `text` | Клиент собеседнику через сервер | `text` — строка |
| `peer_left` | Сервер оставшемуся | `role` вышедшего |
| `error` | Сервер отправителю | `message` — описание ошибки |

Первым сообщением после успешного входа приходит `joined`, например
`{"type":"joined","room_id":"abc","role":"speech","participants":2}`.
Счётчик в нём отражает состояние при входе. Первый участник узнаёт
о приходе второго из `peer_joined`.
Ожидающий участник, получивший `peer_joined`, создаёт offer. Вошедший
вторым участник ожидает offer и отправляет answer. Это позволяет избежать
одновременного создания двух offer. ICE-кандидаты, пришедшие до установки
remote description, фронтенд ставит в очередь.

Примеры сообщений клиента.

```json
{"type": "text", "text": "Привет!"}
```

```json
{"type": "offer", "data": {"type": "offer", "sdp": "..."}}
```

```json
{"type": "answer", "data": {"type": "answer", "sdp": "..."}}
```

```json
{"type": "ice_candidate", "data": {"candidate": "candidate:...", "sdpMid": "0", "sdpMLineIndex": 0}}
```

`data` передаётся второму участнику без изменения. Отправляй реальные
значения из RTCPeerConnection, для ICE — `event.candidate.toJSON()`.
При `event.candidate === null` отправку пропускай.
Текст и signaling отправляются только собеседнику. Истории и подтверждений
доставки нет. При отсутствии собеседника отправителю возвращается `error`.
Некорректный JSON, неизвестный type и неправильные поля также дают `error`.

Несуществующая комната, неверная/занятая роль и третий участник приводят
к отказу до принятия WebSocket. HTTP handshake возвращает 403.
Браузер обычно сообщает лишь ошибку соединения. Не рассчитывай получить
JSON error или close code 1008 при таком отказе.

После `peer_left` закрой старый RTCPeerConnection. Пока один участник
остаётся в комнате, освободившуюся роль может занять новый участник.

## Изображения

`POST /hands` принимает один JPEG/PNG через multipart, поле `file`.
Максимум файла — 5 × 1024 × 1024 байт. Не задавай Content-Type вручную,
браузер должен добавить multipart boundary.

```javascript
const form = new FormData();
form.append("file", imageBlob, "frame.jpg");
const response = await fetch("http://127.0.0.1:8000/hands", {
  method: "POST",
  body: form,
});
const result = await response.json();
if (!response.ok) throw new Error(result.detail);
console.log(result.hands);
```

Ответ 200 имеет форму
`{"hands":[{"side":"Left","points":[{"x":0.42,"y":0.67,"z":-0.03}]}]}`.
В этом примере сокращён список точек. В реальном ответе на руку 21 точка,
максимум две руки. Порядок рук между кадрами может меняться.
`x`, `y` — доли ширины и высоты исходного изображения,
`z` — глубина относительно запястья. Пиксели вычисляются как
`x * imageWidth`, `y * imageHeight`. Без рук ответ `{"hands":[]}`.

Ошибки имеют JSON `{"detail":"описание"}`. Неправильный multipart,
отсутствующее поле или повреждённый JPEG/PNG — 400, слишком большой файл —
413, формат кроме JPEG/PNG или неправильный Content-Type запроса — 415.
Для multipart-запроса предусмотрено дополнительно 64 КиБ на заголовки.
Изображения обрабатываются в памяти. Используй маршрут для отдельных кадров.

## Задачи фронтенда

React + TypeScript реализует страницу комнаты и ссылку приглашения,
getUserMedia, RTCPeerConnection, STUN, отображение потоков и reconnect.
Результат Web Speech API отправляется обычным событием `text`.
Для надёжного соединения в разных сетях позже нужен TURN.
Сервер обрабатывает комнаты, signaling, текст и точки MediaPipe.
Перевод жестов в слова и озвучивание ещё предстоит реализовать.
